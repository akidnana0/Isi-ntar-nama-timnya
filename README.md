# Arsitektur Sistem

## 1. Bagian Interface

### a. Input Interface
Aliran Data: `HPS Side (AXI3 Master, 64 bit) -> h2f bridge -> FPGA Side (AXI3 Slave, 64 bit) -> Input FIFO -> Core Side (AXI4 Stream-Master, 64 bit)`

| Nama Block | Size | Deskripsi |
| :--- | :--- | :--- |
| **Address_In** | 32 bit | This is the AXI3 write address. The HPS DMA controller uses this 32-bit address to specify where in the FPGA's memory-mapped space the incoming document data should be written. Since the Cyclone V uses a 32-bit address space for the HPS-to-FPGA bridge, this width is sufficient to address up to 4 GB of FPGA slave space. |
| **Data_In** | 64 bit | This is the AXI3 write data payload. It carries the raw bytes of the e-Meterai PDF document from the HPS DDR3 into the FPGA fabric. The 64-bit width matches the HPS DDR3 memory bus and the native word size of SHA-512, ensuring efficient data transfer without padding or packing overhead. |
| **BRESP** | 2 bit | This is the AXI3 Write Response channel. After the Input FIFO successfully receives a burst of data, it asserts BRESP to acknowledge the write. The 2-bit code indicates the status: 00 (OKAY), 01 (EXOKAY), 10 (SLVERR), or 11 (DECERR). This tells the HPS DMA controller whether the transfer was successful or if an error occurred. |
| **l3_main_clk** | 1 bit | This is the main clock for the HPS L3 interconnect. It is the clock domain in which the ARM Cortex-A9 and its DMA controller operate (typically around 100-200 MHz on the DE10-Nano). The h2f bridge uses this clock on its HPS-side interface. |
| **TDATA** | 64 bit | This is the AXI4-Stream data payload. It carries the document bytes from the Input FIFO to the SHA-512 Implementation Plane. Unlike the memory-mapped AXI3 interface, TDATA has no address—it is a continuous stream of 64-bit words that the Block Splitter will assemble into 1024-bit blocks for SHA-512 processing. |
| **TVALID** | 1 bit | This is the AXI4-Stream valid signal. When asserted, it indicates that the data on TDATA is valid and ready to be consumed by the Block Splitter. It works in conjunction with TREADY (which points left, from the Block Splitter back to the FIFO) to implement the standard AXI-Stream handshake. |
| **TLAST** | 1 bit | This is the AXI4-Stream last signal. It is asserted on the final 64-bit word of a document. This tells the Block Splitter that the current document has ended, triggering the SHA-512 padding logic (appending the 1 bit, zeros, and the 128-bit length field) before the final block is hashed. |
| **TUSER** | 16 bit | This is the AXI4-Stream user sideband signal, carrying the Job ID. The HPS assigns this 16-bit ID to each document before sending it. The Input FIFO passes it alongside the document data so that the SHA-512 cores can hold onto it during computation. This ensures the final hash can be matched back to the correct PDF. |
| **h2f_axi_clk** | 1 bit | This is the FPGA-side clock for the HPS-to-FPGA bridge. It is generated by the FPGA fabric (typically 50-100 MHz on the DE10-Nano) and is used by the Input FIFO's AXI3 slave interface. The h2f bridge internally handles the clock domain crossing. |
| **core_clk** | 1 bit | This is the clock domain for the SHA-512 Implementation Plane. It drives the read side of the Input FIFO's dual-clock FIFO and the Block Splitter logic. |

### b. Output Interface
Aliran Data: `Core Side (AXI4 Stream-Slave, 512 bit) -> Output FIFO -> FPGA Side (AXI3 Master, 64 bit) -> f2h bridge -> HPS Side (AXI3 Slave, 64 bit)`

| Nama Block | Size | Deskripsi |
| :--- | :--- | :--- |
| **Address_Out**| 32 bit | This is the AXI3 write address. The Output FIFO generates this 32-bit address to tell the f2h bridge where in the HPS DDR3 the result packet should be written. The driver allocates a result buffer in DDR3 and programs its base address into the Output FIFO's control registers. |
| **Data_Out** | 64 bit | This is the AXI3 write data payload. It carries the result packet (Job ID + 512-bit SHA-512 digest) from the Output FIFO to the HPS DDR3. The Output FIFO internally splits the 512-bit digest into 8 x 64-bit words to match this bus width. |
| **BRESP** | 2 bit | This is the AXI3 Write Response channel. After the f2h bridge successfully writes the result packet to HPS DDR3, it asserts BRESP to acknowledge the write. The Output FIFO's AXI3 Master FSM waits for this response before sending the next result packet. |
| **l3_main_clk**| 1 bit | This is the main clock for the HPS L3 interconnect. The f2h bridge uses this clock on its HPS-side interface to forward the result packet to the DDR3 memory controller. |
| **TDATA** | 512 bit| This is the AXI4-Stream data payload. It carries the 512-bit SHA-512 digest from the Result Aggregator to the Output FIFO. Because SHA-512 natively produces a 512-bit output, this interface is 512 bits wide, allowing the entire digest to be transferred in a single clock cycle. |
| **TVALID** | 1 bit | This is the AXI4-Stream valid signal. When asserted, it indicates that the 512-bit digest on TDATA is valid and ready to be written into the Output FIFO. |
| **TLAST** | 1 bit | This is the AXI4-Stream last signal. It is asserted to mark the end of the result packet. |
| **TUSER** | 16 bit | This is the AXI4-Stream user sideband signal, carrying the Job ID. The Result Aggregator re-attaches the Job ID to the 512-bit digest. |
| **f2h_axi_clk**| 1 bit | This is the FPGA-side clock for the FPGA-to-HPS bridge. It is generated by the FPGA fabric (typically 50-100 MHz on the DE10-Nano) and is used by the Output FIFO's AXI3 master interface. |
| **core_clk** | 1 bit | This is the clock domain for the SHA-512 Implementation Plane. It drives the write side of the Output FIFO's dual-clock FIFO and the Result Aggregator logic. |

## 2. Bagian FSM (Finite State Machine) & Register

### Register Control Bank

| Blok Register | Offset | Akses | Deskripsi |
| :--- | :--- | :--- | :--- |
| **CTRL** | `0x00` | R/W | **Bit [0] START:** Write 1 to begin processing.<br>**Bit [1] RESET:** Write 1 to reset all SHA-512 cores and internal FIFOs.<br>**Bit [2] FLUSH:** Write 1 to flush the Input/Output FIFOs.<br>**Bit [3] IRQ_GLOBAL_EN:** Global interrupt enable.<br>**Bits [7:4] CORE_COUNT:** Number of active cores (1-16).<br>**Bits [31:8]:** Reserved (0). |
| **STATUS** | `0x04` | R | **Bit [0] BUSY:** 1 if any enabled core is active.<br>**Bit [1] DONE:** 1 if all submitted jobs have completed.<br>**Bit [2] ERROR:** 1 if any error has occurred.<br>**Bit [3] IDLE:** 1 if all cores are idle.<br>**Bits [31:4]:** Reserved. |
| **CORE_EN** | `0x08` | R/W | **Bits [15:0]:** Each bit enables/disables a specific SHA-512 core (e.g., Bit 0 = Core 0).<br>**Bits [31:16]:** Reserved (0). |
| **IRQ_EN** | `0x0C` | R/W | **Bit [0]:** Enable job completion interrupt.<br>**Bit [1]:** Enable error interrupt.<br>**Bit [2]:** Enable FIFO overflow interrupt. |
| **IRQ_STATUS**| `0x10` | R/W1C| **Bit [0]:** Job completion interrupt pending.<br>**Bit [1]:** Error interrupt pending.<br>**Bit [2]:** FIFO overflow interrupt pending. (Write 1 to clear). |
| **JOB_BASE** | `0x14` | R/W | **Bits [31:0]:** The 32-bit physical address in HPS DDR3 where the job descriptor queue is located. |
| **JOB_COUNT** | `0x18` | R/W | **Bits [31:0]:** The number of jobs currently in the queue. |
| **VERSION** | `0x1C` | R | **Bits [31:0]:** Hardcoded 32-bit value (e.g., 0x00010001) for driver validation. |
| **CORE_STATUS**| `0x20` | R | **Bits [15:0]:** Busy/idle state of specific cores (1=Busy, 0=Idle). |
| **ERROR_FLAGS**| `0x24` | R/W1C| **Bit [0]:** AXI protocol error.<br>**Bit [1]:** Core timeout.<br>**Bit [2]:** FIFO underflow/overflow. |

### Fungsi Blok FSM

| Fungsi | Deskripsi |
| :--- | :--- |
| **Writing** | **IDLE:** Waits for AWVALID.<br>**WRITE_ADDR:** Captures AWADDR, asserts AWREADY.<br>**WRITE_DATA:** Captures WDATA/WSTRB, asserts WREADY.<br>**WRITE_REG:** Asserts reg_wr_en pulse. Writes WDATA to AWADDR.<br>**WRITE_RESP:** Asserts BVALID, sets BRESP = 00 (OKAY).<br>**DONE:** Returns to IDLE. |
| **Reading** | **IDLE:** Waits for ARVALID.<br>**READ_ADDR:** Captures ARADDR, asserts ARREADY.<br>**READ_REG:** Sets reg_addr to ARADDR, places value on reg_rdata.<br>**READ_DATA:** Captures reg_rdata, asserts RVALID, sets RRESP = 00.<br>**DONE:** Returns to IDLE. |

### Blok Kontrol Lainnya

| Blok | Deskripsi |
| :--- | :--- |
| **Core Manager** | **Clock Gating/Power Saving:** Reads `CORE_EN`. Gates clock and holds reset for disabled cores. Enables clock and releases reset for enabled cores.<br>**Job Launch:** Watches `CTRL[START]=1` to allow cores to pull data.<br>**Completion Tracking:** Monitors `core_done`. Asserts `all_done` when finished, updating `STATUS[DONE]=1`. |
| **Interrupt Controller & HPS GIC** | **FPGA Side:** Sets `IRQ_STATUS` bits based on `core_done` or errors. If enabled via `IRQ_EN`, asserts `fpga_irq` wire.<br>**HPS GIC:** Maps `fpga_irq` to specific IRQ ID (e.g., 72), interrupts ARM CPU, jumping to Linux driver handler. |

## 3. Bagian SHA-512

| Blok | Deskripsi |
| :--- | :--- |
| **Block Splitter** | Acts as the bridge between the 64-bit streaming world (Interface) and the 1024-bit block world of SHA-512. Accumulates 64-bit words into 1024-bit blocks. Handles mandatory cryptographic padding (appending 1 bit, zeros, and 128-bit length) when `TLAST` is asserted. Captures and propagates the Job ID (`TUSER`). |
| **Work Dispatcher** | Traffic controller and scheduler. Parallelizes at the document level (different documents to different cores) since SHA-512 is inherently sequential per document. Uses First-Free/Round-Robin to assign new documents to idle cores. Maintains a Job ID -> Core tracking table to route subsequent blocks sequentially. |
| **12 Core SHA-512**| The actual cryptographic engine array executing the SHA-512 algorithm across 12 parallel cores. |
| **Result Aggregator**| Final collection stage. Handles out-of-order completions from cores using a round-robin arbiter. Pairs the 512-bit digest with its Job ID (`TUSER`). Packages it into a single AXI4-Stream beat (`TVALID=1`, `TLAST=1`) and sends it to the Output FIFO. |

## 4. Bagian Software

| Blok | Deskripsi |
| :--- | :--- |
| **Application Interface** | The user-facing program (CLI, Web server, batch processor). Translates human requests into library calls. Calls `sha512_verify_file(path)` and reports VERIFY_OK, VERIFY_TAMPERED, or VERIFY_ERROR. |
| **User Space Library** | Shared library (`.so`) hiding PDF parsing, X.509 extraction, and driver interaction. Opens PDF, finds `/ByteRange` and `/Contents`, parses PKCS#7 to extract X.509 and expected hash. Opens `/dev/sha512`, allocates job, sends data via `write()` or `mmap()`, reads computed hash via `read()`, and compares it. |
| **Kernel Driver** | Character device driver (`/dev/sha512`) managing FPGA registers, DMA, and interrupts. Includes:<br>- `probe()`: ioremap, DMA allocation, IRQ request.<br>- `open()` / `release()`: Session management.<br>- `ioctl()`: Set cores, submit jobs, reset.<br>- `write()`: Program PL330 DMA, write registers, kick off start.<br>- `read()`: Wait on queue, invalidate CPU cache, copy result to user space.<br>- `Interrupt Handler`: Clears IRQ, reads results, wakes waiting processes. |
| **DMA Engine Integration** | Linux kernel `dmaengine` subsystem. Abstract API for PL330 DMA. Uses `dma_request_channel()`, `dmaengine_prep_dma_memcpy()`, and `dmaengine_submit()` to handle memory transfers efficiently via callbacks. |
